# Cloudflare Research Findings (2026-08-12)

Cloudflare's official Python Workers documentation states that Python Workers support packages including FastAPI and Pydantic, use a `Default(WorkerEntrypoint)` class with an async `fetch` handler, and require the `python_workers` compatibility flag while the feature is in open beta. Deployment is performed with `pywrangler deploy`. Source: https://developers.cloudflare.com/workers/languages/python/

Cloudflare's secrets documentation states that API keys and auth tokens should be stored as encrypted Worker secrets, accessed through the `env` parameter. Local `.dev.vars` or `.env` files must not be committed to Git. Production secrets can be added with `wrangler secret put`, through the dashboard, or through the Workers Secrets API. Plaintext `vars` are not appropriate for sensitive credentials. Source: https://developers.cloudflare.com/workers/configuration/secrets/

Implementation decision: use a Python Worker entrypoint for the backend, use Cloudflare secrets for all API credentials and the Google service-account JSON, and keep all frontend code free of secret values. The Worker will implement CORS with an allowlist for the GitHub Pages origin, use Google Places API for business discovery, use Firecrawl only for public website enrichment where configured, and write to Google Sheets through a service-account token generated at runtime from the secret JSON. The project will retain a conventional FastAPI-compatible local entrypoint for local development but use the Cloudflare Worker entrypoint for deployment.
